How this handbook is organized

It follows the product's own shape: admin features grouped exactly as they appear in the dashboard's left-hand navigation, then the storefront a shopper actually sees. Every feature gets what it does, the fields you'll fill in, and — set apart in a callout — the rules that aren't obvious from the screen alone.

Signing in

OMEcommerce is two separate apps: the admin back office your team runs the store from, and the storefront your customers shop on. They have separate accounts and separate logins.

Admin login

Every admin page requires a signed-in session — there's no browsing the dashboard while logged out.

  1. Open the admin app and go to /admin/login.
  2. Enter your admin email and password.
  3. You're dropped onto the Dashboard, with the full sidebar available for whatever permissions your account has.

Screenshot: the admin sign-in screen.

Storefront: browsing without an account

Most of the storefront works whether or not a shopper is signed in.

You can browse, search, add items to a cart, and check out entirely as a guest — an account only unlocks order history, saved addresses, wallet, rewards, referrals, and company access. A guest's cart is remembered by the browser, not tied to any login.

Create an account

Go to /register — or the "Create an account" link on the sign-in page.

FieldNotes
First nameRequired.
Last nameOptional.
EmailRequired, must be a valid address.
PasswordRequired, at least 8 characters.

Click Create account and you're signed in immediately and dropped onto /account.

Good to know

Arrived via a shared referral link (a URL ending in ?ref=CODE)? The code rides along through registration automatically. If it's expired or invalid it never blocks account creation — you just get a toast saying the link couldn't be applied, and your account is created regardless.

Sign in

Go to /login.

Enter your email and password and click Sign in. A wrong password shows an inline error without saying which of email/password was wrong.

01

Catalog & Inventory

Everything about what you sell: the products themselves, the reusable attributes that describe them, the category tree shoppers browse, and how much of each you have where.

Products

Create and manage everything in the catalog — simple items, configurable products with size/color variants, bundles, digital and virtual goods.

Sidebar → Catalog → Products — /products

Finding a product

The list has a search box (matches SKU or name), and dropdown filters for Status, Type, and Attribute Set. Column headers for SKU, Name, Created, and Status are sortable — click one to toggle ascending/descending. Each row also shows a Tax badge: "GST" if a tax class is assigned, or "None" if the item is charged zero tax at checkout.

Select rows with the checkboxes to reveal a bulk bar with Activate and Deactivate — handy for taking a batch of products live or off-sale at once.

Screenshot: the Products list, filters expanded, a few rows selected.

Creating a product

New Product button → /products/new

  1. Fill in SKU and pick a Type — Simple, Configurable, Bundle, Digital, or Virtual. Choosing Configurable adds a note that you'll generate its Size/Color variants after saving.
  2. Pick an Attribute set — this decides which extra fields appear below, since every product must belong to exactly one set.
  3. Fill in Name and, if relevant, Weight (kg).
  4. Set Status (starts as Draft) and, under Tax, a Tax Class plus an HSN/SAC code if this item is taxed.
  5. Work through the attribute fields the chosen set brought in — Description and SEO fields are always present; everything else depends on the set.
  6. Tick the Categories this product should appear under.
  7. Click Create Product. You land on the new product's detail page.
Read before you click

SKU and Type can never be changed once the product is created. Leaving an attribute field blank simply omits it — there's no separate "clear this value" action. Ticking zero categories replaces the full assignment with nothing, so an empty checklist really does remove the product from every category it was in.

Editing, variants, pricing, and images

Open a product → Edit — /products/{id}/edit

The main form covers Name, Attribute Set, Weight, Status, Visibility, Tax Class/HSN, attributes, and categories — SKU and Type are shown locked. Three more sections live on the same page, each saving independently:

  1. Variants (Configurable products only) — tick which attributes form the variant axes (e.g. Size, Color), tick which of their option values to include, and click Generate Variants to create every combination at once, each with an auto-built SKU. Existing variants can be edited (SKU, Active/Inactive) or deleted from the table below.
  2. Pricing & Inventory — per variant, a pricing table (one row per price list, Set Price to fill it in) and an inventory table (one row per warehouse, Adjust to change stock — see Inventory below for how adjustments work).
  3. Images — Add Images uploads one or more files; hover any thumbnail for Set as Main and Delete. The main image is what shows on the storefront's grid, product page, mini-cart, and cart.

Screenshot: a Configurable product's edit page with the Variants and Pricing & Inventory sections open.

Can't be undone

Deleting a product or a single variant is blocked while it still has stock in any warehouse — zero out its stock first. Past orders are safe either way, since every order line keeps its own snapshot of the name, SKU, and price at the time of purchase.

Attribute sets

Groups of attributes a product picks up all at once. Every product has exactly one set, and everything assigned to that set shows up on the product's edit page.

Sidebar → Catalog → Attribute Sets — /attribute-sets

  1. Click New Attribute Set, give it a Code and Name, and optionally mark it the Default set (the one pre-selected on the New Product form).
  2. Open the set to organize it into Groups (e.g. "General", "Dimensions") — each needs a Name and a Sort Order.
  3. Inside a group, click Assign Attribute to pull in an attribute from the reusable library (search by code or label), with a Sort Order for where it lands.
Good to know

Removing an attribute from a set doesn't delete any values already stored on products — it just stops showing the field. A set can't be deleted while any product still uses it.

Attributes

The reusable field library — build an attribute once here, then assign it into whichever Attribute Sets need it.

Sidebar → Catalog → Attributes — /attributes

FieldNotes

Read before you click

Data type and Input type lock once an attribute is created — changing them later could invalidate values already stored against it. Only a Select attribute (not Multiselect) marked Variant Forming can drive variant generation on a product.

Categories

The navigation tree shoppers browse by.

Sidebar → Catalog → Categories — /categories

The list is a tree — each row has Edit and Delete. New Category asks for a Name and a Parent (defaults to root). There's no separate read-only detail view; Edit is the only page per category, covering Name, Parent, Position, Sort Mode (manual, name, price, or newest-first), whether it's included in the storefront menu, an image, description, and SEO meta fields.

Good to know

The slug is fixed at creation. Hiding a category from the menu also hides everything nested under it. A category can never be re-parented under itself or one of its own children.

Inventory

Per-warehouse stock levels, and the one place you adjust them by hand.

Sidebar → Catalog → Inventory — /inventory

Chips across the top switch which warehouse's stock table you're viewing (On Hand, Reserved, Available per SKU). To change a number, click Adjust on a row, or use the page-level Adjust Stock button and search by SKU first — it accepts either a base product SKU or a full variant SKU.

  1. Enter the Quantity change — this is a delta, not a new total. Positive adds stock, negative removes it (a helper link fills in the exact negative number needed to zero out the current On Hand).
  2. Pick a Reason: Purchase, Return, Adjustment, Transfer, or Correction.
  3. Add an optional Note, then click Adjust Stock.

Screenshot: the Adjust Stock dialog, quantity-change step.

Warehouses

The fulfillment locations stock is held at.

Sidebar → Catalog → Warehouses — /inventory/warehouses

New Warehouse asks for Code (permanent), Name, and Type (Physical, Virtual, or Dropship). Editing adds Priority (higher-priority warehouses are preferred when an order could be fulfilled from more than one location) and a Status toggle.

Good to know

Setting a warehouse to Inactive is the safe way to retire it — its history stays intact and it doesn't need zero stock first. Actually deleting one does require zero stock everywhere.

Pricing

Price lists — base retail pricing plus wholesale, B2B, or scheduled special pricing — and the prices set on each.

Sidebar → Catalog → Pricing — /pricing

New Price List asks for Code (permanent), Name, Currency, Type (Base, Wholesale, B2B, Special), and Priority — when more than one list could apply to a sale, the higher-priority one wins. Set Price on any list uses the same SKU-search flow as Inventory adjustments: find the variant, then enter its Price.

Good to know

Deleting a price list is really a deactivation — it stops applying immediately, but any prices already set on it are kept, not erased. Which customers see a B2B/wholesale list is controlled by the Customer Group set on their Company, not from this page.

02

Commerce & B2B

Orders from placement through to closing the book, customer accounts and their wallets, discount coupons, and the B2B company accounts that unlock special pricing and tax terms.

Orders

Everything that's been bought — filter and export the list, then work each order through fulfillment, invoicing, and (when needed) refunds and cancellation.

Sidebar → Commerce → Orders — /orders

Finding orders

Filter by order number, email, customer name, Status, Payment Status, Fulfillment Status, and a date range. Export CSV / Export Excel download whatever the current filters return.

An order's detail page

Every order opens onto five tabs — Information (customer, addresses, payment/shipping method, line items, notes, and the full totals breakdown), Invoices, Shipments, Emails (an audit log of every email sent), and Comments History (the full activity feed). The action bar at the top offers whichever of Fulfill, Refund, Create Invoice, Send Email, Close Order, and Cancel Order currently apply.

Screenshot: an order's Information tab, action bar visible.

Fulfilling an order

  1. Click Fulfill (shown only once there's unshipped quantity remaining).
  2. Adjust the quantity to ship per line — it defaults to the full remaining amount.
  3. Fill in Carrier, Tracking Number, Carrier Tracking URL, Estimated Delivery, and any Shipping Notes.
  4. Click Fulfill to create the shipment.
Read before you click

An order has to be PAID before it can be fulfilled — an unpaid order rejects the request.

Refunding, cancelling, and closing

ActionWhat it doesRequires
RefundRefund some or all of specific lines, optionally restocking them. Amount is proportional — a coupon-discounted item is refunded for what was actually paid.Order is Paid or Partially Refunded; can't exceed a line's remaining refundable quantity.
Cancel OrderRefunds every remaining line in full, restocks, and closes the order out as Cancelled.Nothing has shipped yet. Once any line has been fulfilled, cancel is blocked — use Refund for the fulfilled portion instead.
Close OrderMarks the order as fully settled — a distinct terminal state from simply "Completed."Every line fully shipped, and financial status Paid or Refunded.
Can't be undone

Cancel Order and Close Order both ask for a final confirmation and can't be reversed from the admin UI once confirmed.

Invoicing and emailing

Create Invoice generates a PDF for some or all of the order's uninvoiced quantity — you can invoice the same order more than once as it partially ships. Send Email manually (re-)sends a transactional message: Order Confirmation, Invoice, Shipment Notification, Cancellation Notice, Refund Notice, or a fully Custom Message with its own subject and body.

Customers

Every registered shopper's profile, and the wallet, loyalty, and referral activity tied to their account.

Sidebar → Commerce → Customers — /customers

Search by name or email. Opening a customer gives four tabs:

WalletStore-credit balance and transaction history, plus Credit, Adjust, and Freeze/Unfreeze actions.
LoyaltyPoints balance, lifetime points, current tier, and an Adjust Points action.

Coupons

Discount codes — a flat percentage or fixed amount off, applied to the whole cart or targeted at specific items, entered manually or auto-applied.

Sidebar → Commerce → Coupons — /coupons

  1. Click New Coupon and set a Code (permanent) and optional internal Description.
  2. Choose Discount Type — Percentage or Fixed Amount — and its Value. Fixed Amount also needs a Currency and unlocks an optional Minimum order subtotal.
  3. Set Applies to — Whole Cart, or Specific Items (which opens the condition builder below) — and whether it's Auto-Apply or requires a code typed at checkout.
  4. For Specific Items, add one or more conditions — match by Product/SKU, Category, or Attribute. A line must match every condition to qualify.
  5. Set Usage limit, Per-customer limit, and a Start/End window, then Status.
  6. Click Create Coupon.
Read before you click

The code can't change after creation. A SKU typed into a condition row is looked up at save time — a typo that matches nothing will fail the save with "no product found for that SKU." Deleting a coupon stops it working immediately but keeps its redemption history.

Companies (B2B)

Business/wholesale buyer accounts — a company groups a set of shopper logins under shared pricing and tax terms.

Sidebar → B2B → Companies — /companies

Registering a company

  1. Click New Company.
  2. Pick the Website it belongs to and set a Code — both are permanent once saved.
  3. Fill in Name, and optionally a Customer group code — this is what controls which price list the company's buyers see; leave it blank and they default to ordinary retail pricing.
  4. Under Tax, set Tax exempt if this company doesn't pay tax on its orders — a Tax exemption reference becomes required the moment you switch this on.
  5. Optionally add a Billing Contact name, email, and phone.
  6. Click Create Company.

Screenshot: the New Company form, Tax section expanded with exemption reference required.

Approving and managing status

A new company starts as PENDING — its members shop as ordinary retail customers until it's approved. From the company's detail page:

Current statusAvailable actions
PENDINGApprove → Active, or Reject → Rejected.
ACTIVESuspend → Suspended.
SUSPENDED / REJECTEDReactivate → Active.
Good to know

Only an Active company grants its members B2B pricing and tax exemption — a Pending, Suspended, or Rejected company's members simply get treated as retail customers, with no error shown anywhere. No status is a dead end; any of them can be moved back to Active.

Managing members

On the company's detail page, Add Member takes an email (must already be a registered customer on that website) and a Role — Buyer or Admin. Each existing member gets a Role dropdown and a Remove button.

Read before you click

A customer can belong to at most one company at a time — adding someone already on another company's roster fails. Removing a member drops their B2B access but doesn't touch their customer account. Role (Buyer vs. Admin) only affects who can manage the member list on the storefront side — both roles can place B2B orders once the company is Active.

03

Loyalty & Rewards

Gift cards you issue by hand, and the points and referral programs that run themselves once configured — earning, tier upgrades, and clawback on refund all happen automatically, with nothing to trigger manually.

Gift cards

Digital or physical stored-value cards, issued manually — for phone orders, goodwill gestures, or activating a physical card.

Sidebar → Loyalty & Rewards → Gift Cards — /gift-cards

Issuing a card

  1. Click Issue Gift Card.
  2. Pick the Website, enter the starting Amount, and choose Kind — Digital or Physical.
  3. Optionally fill in Recipient Email, Recipient Name, a gift Message, and an Expiry date.
  4. Click Issue Gift Card.
Can't be undone

The redeemable code is shown exactly once, right after issuing — only a hash is ever stored, so it can never be retrieved or displayed again. Copy it before you navigate away.

Managing an existing card

Open any card for its balance, details, and full ledger (Issue, Redeem, Refund, Adjust, Void, Expire entries). Adjust takes a signed Amount and a required Reason — a debit that would overdraw the balance, or that targets a card that isn't Active, is rejected. Disable permanently blocks further redemption; there's no "re-enable" from this screen, and both buttons disappear once a card is disabled.

Screenshot: a gift card's ledger, Adjust dialog open.

Loyalty program

Configure the earn rate, redemption rules, and tiers — one program per website. Earning and clawback are entirely automatic.

Sidebar → Loyalty & Rewards → Loyalty Program — /loyalty

FieldControls
Points per currency unitHow many points a customer earns per unit spent.
Value per pointThe store-credit value of one point when redeemed.
Minimum points to redeemBalance floor before any redemption is allowed.
Points expire after (months)Blank means points never expire.
StatusActive, Paused, or Ended (edit mode only).

Below the settings, a Tiers table (Name, Threshold points, Earn multiplier, Sort order) with Add Tier, and per-row Edit/Delete.

Good to know

Points are earned the moment an order is paid and clawed back proportionally on refund — there's no manual "award points" button here (per-customer manual adjustments live on the customer's own Loyalty tab instead). Tier is re-evaluated automatically every time a customer earns; deleting a tier just drops its members back to no tier until their next order re-sorts them.

Referrals

The "refer a friend" program — configure it per website and watch the results; qualification and reward issuance are fully automatic.

Sidebar → Loyalty & Rewards → Referrals — /referrals

FieldControls
Qualifying eventOn sign-up, or on the referee's first paid order.
Minimum order amountOnly for first-order qualifying — the order must reach this to count.
Referrer / Referee rewardEach side gets its own Store Credit or Loyalty Points reward.
Max referrals per customerBlank means unlimited.
Attribution window (days)How long after signup a first order can still qualify.

Below the settings, a filterable, read-only report of every referral: referrer, referee, status, rewards, and the signed-up/qualified/rewarded dates.

Read before you click

Picking Loyalty Points as a reward type only works once this website already has a loyalty program configured. If an attribution window is set and it lapses before the referee orders, that referral is marked Expired automatically — even a later order won't revive it.

Storefront

What a shopper actually sees — browsing and search, the cart, a five-step checkout, and everything under their account.

Product listing pages, search, and the product detail page itself.

Screenshot: a product detail page, variant picker and Add to Cart visible.

Good to know

The wishlist heart on a product page toggles instantly for anyone, but only actually saves to the account when signed in — it resets on a fresh page load either way, so the account's real Wishlist page (see below) is the source of truth. The Offers page is promo banners and a popular-picks carousel, not a real discount engine. Reviews and star ratings aren't live yet — the tab just says "No reviews yet."

Cart

Review and adjust items, then apply whatever discounts and stored value are available before checking out.

/cart, or the bag icon in the header for the quick mini-cart drawer.

Each line has a quantity stepper and a remove action. The summary panel totals things up and offers three ways to reduce what's due:

TenderHow it works
CouponType a code and Apply. An auto-applied storewide promo shows without a Remove button — since nothing was typed — but typing a different code overrides it.
Gift cardType a code and Apply — stackable, a cart can hold several at once, each removable on its own.
WalletA single checkbox — pays with the signed-in shopper's own store-credit balance.
Read before you click

Paying with wallet requires being signed in — a guest who checks the box just gets an inline "sign in to pay with your wallet" message. Signing in (or registering) with items already in a guest cart automatically claims that cart and re-checks its pricing under your account — including B2B pricing, if you belong to a company.

Checkout

A five-step flow from shipping address to a placed order.

/checkout — redirects back to the cart if it's empty.

  1. Shipping — email and the delivery address (name, phone, address lines, city, state, postal code, country; a GST state and optional GSTIN for an Indian business invoice).
  2. Billing — "Same as shipping" is checked by default; uncheck it to enter a separate billing address.
  3. Delivery — pick a shipping method from the priced list.
  4. Payment — this store uses a test gateway: no real card is charged and no card details are collected. A "simulate result" dropdown lets you deliberately test an approved or declined payment. If wallet/gift-card tenders already cover the full total, this step just confirms that and skips asking for a card.
  5. Review — a final look at the order, then Place Order.

Screenshot: the checkout wizard's Payment step, test-gateway note visible.

Placing the order lands on /checkout/success/{orderId} with the order number, confirmation email address, full line items, tax breakdown, and total.

A few things worth knowing

Good to know

Addresses has no edit — changing one means deleting it and adding a new one, and there's no "default address" concept. Reorder adds a past order's items to a fresh cart and warns if any SKU is no longer available, adding the rest regardless. On Rewards or Referrals, a store with no active program simply shows a friendly "not available right now" message rather than an error. On Company, member management only appears for Admin-role members — Buyers never see it, and can't reach it by URL either.
